2026-05-19 straight-punch design pass

Trustworthy enough to keep using

  • shoulder_width normalization still looks usable as the main per-athlete ratio surface.
  • Handed landmark ownership still looks good enough to treat left/right as separate per-side models; the reverted kept run did not spontaneously emit punch_right.
  • Current 2D horizontal placement like outward_distance is still useful as a side lock / lane ownership clue, even though it is a bad extension measure for forward punches.
  • Depth bursts matter: forward_velocity spikes in authored windows 1-3 line up with real punch effort much better than the old lateral-only straight-punch gates.
  • The existing one-shot fire / explicit rearm idea in pose_detector_substrate.gd is still the right overall state shape; what failed was the metric truth, not the need for state.

Misleading on front-facing forward straights

  • 2D arm_extension and 2D elbow_bend_deg lie badly on the authored forward punches. They repeatedly read “not extended / not straight” while temporary 3D comparison values show the opposite.
  • 2D outward_distance is also misleading as a fire threshold for straights. It is a lateral reach proxy, not a forward punch truth signal.
  • Absolute forward_distance is too sticky to own the detector. It stays elevated across large portions of the clip, so it cannot truthfully decide retraction by itself.
  • Raw forward_velocity alone is too noisy. The clip has large depth-velocity swings outside authored windows too.
  • Naive 3D straightness alone is not a rearm signal. In the final preserved run, arm_extension_3d >= 0.92 for 131 / 176 captured samples, which is exactly why the quick 3D patches spammed.
